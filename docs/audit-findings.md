# Audit Findings

Findings from phase 5's audits, [step 5.1](phase5-plan.md#51-audit-bugs-and-design) (bugs and design) and [step 5.2](phase5-plan.md#52-audit-performance-baseline-and-profiles) (performance leads). Moved out of [phase5-plan.md](phase5-plan.md) on 2026-10-30 to keep that plan short; the tables are unchanged. Open items are worked through from here, and each fix is marked in its row's **Decision** column. One table for bugs and design, one for performance leads.

## Passes so far

**First pass 2026-10-30.** In the order step 5.1 gives: the app first, then `omp-core`, then `omp-builder`. Read in full: `app.rs`, `printui.rs`, `routing/{mod,panel,worker}.rs`, `pins.rs`, `trips.rs`, `files.rs`, `config.rs`, `main.rs`, `packs.rs`, `loader.rs`, `verify.rs`, `side.rs`, `printer/{gdi,cups}.rs`. Read in part: `labels.rs` (extraction and placement), `style.rs` (compile), `render.rs` (paints, frame, readback), `snapshot.rs` (tile loading), `routing/times.rs`, `search/worker.rs`. `omp-core`: searched for panics on damaged data (indexing with decoded values, `unwrap`/`expect`) in `pack`, `tiles`, `tile`, `route/*`, `admin`, `tz`; the readers check bounds, and every `expect` left holds by construction. `omp-builder`: the build's stages, staging and pack replacement (`build/mod.rs`). Six bugs fixed (B1–B6 below), with tests for B3, B4 and B6.

**Second pass 2026-10-30.** Read in full: the rest of the app (`here`, `search/{mod,session,ui,draw}`, `routing/{line,saved}`, `camera`, `pages`, `pdf`, `print`, `text`, `shapes`, `mesh`, `tiles`, `cache`, `pool`, `layers`, `scale`, `theme`, `logger`, `memory`, `printer.rs`, `printer/none.rs`; `bench.rs` skimmed, as a dev tool). In `omp-core`: `varint`, `zframe`, `geo`, `grid`, `blocked`, `fuzzy`, `meta`, `schema`, `whitelist`, `here`, `routes`, `street`, `addr`, `search`, `find/{mod,hits,numbers}`, `schedule`, the readers in `route/mod.rs` and the search and unpacking in `route/query.rs`; `find/{candidates,readings,score}`, `query` and `normalize` scanned for byte slicing and `unwrap` (every slice is at an ASCII digit boundary). In `omp-builder`: `main`, `build/cache.rs`, `fetch/{http,mod}.rs`, every module's head, and every `unwrap`/`expect` in production code (each holds by an earlier filter, or reads the builder's own temp data). Three bugs fixed, B7–B9, with tests for B7 (ignored: it needs a pack and a GPU) and B9 (which hung before the fix); R6–R8, D15–D16 and leads P1–P3 found. R8 matters most: the app's release build aborts on any panic, so R1 and the loader's and print worker's catches need the owner's decision on it.

**Third pass 2026-10-30.** Read in full: in `omp-core`, `route/{guide,order,trip,alt,matrix}`, `profile`, `tile`, `tiles`, `pack`, `admin` and `tz`; in `omp-builder`, the stages `geom`, `pbf/{mod,nodes,features}`, `graph/{mod,read,restrict,scc}`, `ch/{mod,witness}`, `routing/mod`, `tiles/{mod,water}` and `encode`'s production half, `street/{mod,encode,grid}`, `search/{mod,encode}`, `admin/{mod,read,index,towns,encode}` and `addr/{pipeline,store,sources,tiger,osm,merge,streets,attach,postcodes}`. Not read line by line, as tools rather than stages: `measure`, `report`, `tiles/compress`, `routing/layout`, `ch/check` (all D16's to remove), the builder's `route/*` checks, `find`, `fetch/{manifest,regions,sources}`, `build/{readers,route_readers,inspect,meta}`, `poly` and `tz`. No new bug in the app's paths: the core readers hold up as the first pass found (sums that can overflow on damaged data are R2's). New: R9–R12, D17–D19, P4–P5 and C2; P2 corrected (`build` does not encode MVT). One fix, under D16's decision: `search::encode::sections` compressed all of `SENT` a second time at level 19 in every build, only to print its size without street names (a phase 2 question, settled in 2.6); removed.

| R2 | `omp-core` readers | Damaged sections are only found by *Verify pack*; the readers check bounds, but there is no test that reading damaged data never panics. | risk | Add a test that flips bytes in each section of a small built pack and reads every tile, search and route, expecting errors, not panics. | R8 | `Cargo.toml` `[profile.release]` | The app's release build has `panic = "abort"` (phase 0 Environment, for size), so `catch_unwind` does nothing there: B6's fix in the loader and the print worker's catch work only in tests and debug builds. | R9 | `omp-core` `profile::way`, `parse_maxspeed`; `graph::build`, `ch::witness` | Speeds are not bounded.
